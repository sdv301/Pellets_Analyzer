# Интеграция честной модели v2 (I1–I6)

Источник — санитизированный снимок ветки `cursor/tolko-honest-ml-d3b1` репозитория Tolko_model (архив, не клон: у токена установки Cursor GitHub App репозитория в списке не было). В продукт перенесены парсер, сборка выборки, nested CV и контракт прогноза. Это отдельный пакет `app/services/ml_v2`. Legacy `PelletMLSystem` не заменён.

Не переносились: `lab_teacher_trainer`, `rnf_base_enrichment`, фильтр IQR, фиктивные R²=1.0 как метрика качества, запись прогнозов модели обратно в обучающую таблицу или БД.

## Как переключить и откатить

| переменная | по умолчанию | смысл |
|---|---|---|
| `MODEL_VERSION` | `legacy` | `legacy` — прежний продукт. `v2` — контракт из `app/services/ml_v2/model_store/manifest.json`. |
| `ML_SHADOW_V2` | выключена | Только при `MODEL_VERSION=legacy`. Считает v2 рядом и пишет в лог строку `ml_shadow` (legacy, v2, delta, in_domain). В ответ и в БД разница не попадает. |
| `ML_ALLOW_VERSION_MISMATCH` | выключена | Разрешает загрузить joblib, если major.minor numpy или scikit-learn не совпали с manifest. |

Откат: убрать `MODEL_VERSION` или поставить `MODEL_VERSION=legacy` и перезапустить процесс. Код legacy при этом не меняется, артефакт v2 можно оставить на диске.

Проверка:

```bash
python -m pytest tests/test_v2_parser.py tests/test_v2_contract.py tests/test_v2_switch.py tests/test_v2_auth.py tests/test_v2_evaluation.py
```

Зависимости зафиксированы в `requirements.txt` под образ `python:3.11-slim`. Загрузка артефакта сверяет major.minor `scikit-learn` (1.8) и `numpy` (2.2), не патч-версию Python.

## I1. Снимок legacy

`tests/fixtures/legacy_baseline.json` — текущий `CompositionParser` и `PelletPropertyPredictor.train(algorithm="ridge")` на 48 строках `source=real`.

На рецептах с маслом и листьями legacy-парсер оставляет только опилки и домножает их до 100%. Прогноз такого рецепта совпадает с прогнозом «100% Опилки». Тест `test_legacy_baseline_shows_dropped_oils` падает, если этот снимок разойдётся с текущим парсером: регрессию будет видно.

In-sample R² этого снимка (не метрика v2): q 0.335, density 0.133, kf 0.387, kt 0.844, ad 0.113. Групповой CV той же legacy-модели на этих данных отрицательный.

## I2. Сервис v2

Каталог `app/services/ml_v2/`:

- `components_registry.py` — парсер. Неизвестный фрагмент даёт `ValueError`, масла и листья сохраняются.
- `dataset.py` — `source=real`, группы `recipe_id`, правка `kf` 0.98508 → 98.508 (`kf_raw` сохраняется). IQR нет. Префиксы «Опыт:», «УЧИТЕЛЬ:», «ML-опыт:» в обучение не входят.
- `evaluation.py` — nested leave-one-recipe-out. Масштабирование и подбор гиперпараметров только внутри train.
- `model_contract.py`, `applicability.py`, `predictor.py` — выход на свойство `{value, std, lo90, hi90, in_domain, model_name}` плюс `informative` и `note`. `lo90/hi90 = value ± 1.645·std`.

Артефакт: `app/services/ml_v2/model_store/pellet_models.joblib` и `manifest.json` (версии библиотек, признаки, честные метрики, sha256). Без manifest загрузка отказывается. Признаки — доли компонентов в \[0, 1\], те же, на которых считалась nested CV.

`density`, `kf`, `ad` и любая цель с nested R² ниже 0.2 в ответе — среднее обучающей выборки и её σ, `model_name=baseline_mean`, `informative=false`.

Метрики в manifest взяты из прогона Tolko `artifacts/honest_eval` (2026-11-02), не из in-sample refit. joblib — однократный refit уже выбранной модели на всех 48 real-строках в этом окружении (Python 3.12.3, scikit-learn 1.8.0, numpy 2.2.4).

## I3. Переключатель и тень

Точка входа для роутов — `app/services/ml_v2/switch.py`. Пока `MODEL_VERSION` не равен `v2`, числовой ответ строит legacy. Тень не вызывает запись метрик, строк и `save_ml_model`.

В режиме v2 обучение, автопереобучение и оптимизация состава не запускаются: прежняя оптимизация писала прогноз в обучающую таблицу. Сообщение об ошибке говорит, как вернуться на legacy.

## I4. API, интерфейс, вход

На всех роутах blueprint `ml` стоит `@login_required` (аноним получает редирект на `/login`, не 200).

`/ml_predict` по-прежнему отдаёт числовое поле `prediction`. В v2 рядом лежит `contract` с интервалом и `in_domain`. `/api/predict_composition` сохраняет `value` и `display_name` и в v2 добавляет `std`, `lo90`, `hi90`, `in_domain`, `informative`, `note`.

Песочница показывает «90%: lo … hi», предупреждение «Вне области применимости» и пометку, если вместо модели отдано среднее ± σ. Поля появляются только когда их прислал API, поэтому legacy-карточка остаётся одной цифрой.

## I5. Честные метрики в интерфейсе

Для v2 `/ml_system_status` отдаёт `metrics_kind=nested_cv`. В `training_metrics` нет `r2_train`. Поле `r2_score`, которое читает старый JS, равно nested R² test, а не единице. Карточки подписаны «CV R²». У `density` / `kf` / `ad` бейдж «среднее ± σ». Подпись сводки — «Средний честный CV R²», и в среднее не входят неинформативные цели.

R² train у `q` в manifest равен 1.000 при R² test 0.951. Это in-sample почти линейной зависимости. В UI оно не показывается.

## Открытые вопросы

1. Происхождение колонки `q` не установлено (`q_origin=stored_unverified`). Правило смешения по таблице компонентов в аудите Tolko давало R² около 0.40, а высокий R² модели по `q` этого не доказывает.
2. Перевод `kf` 0.98508 → 98.508 — гипотеза «доля вместо процентов». Если в журнале верно 0.985, нужно вернуть `kf_raw`.
3. 31 значение `strength_limit` может быть и замером, и калибровочной кривой. Код это не различает.
4. σ полного refit (то, что лежит в joblib) у `q` очень узкая: модель почти интерполирует обучающие точки. Множитель conformal в manifest посчитан по OOF и не восстанавливает ширину OOF-интервала. Для решений по новой добавке ориентир — флаг `in_domain`, а не ширина интервала на знакомом рецепте.
5. joblib собран на Python 3.12.3 при библиотеках из `requirements.txt`. Образ Docker — Python 3.11. Загрузчик пускает файл при совпадении sklearn 1.8 и numpy 2.2. Перед продом артефакт стоит один раз пересобрать внутри этого образа (`python -c "from app.services.ml_v2.predictor import build_artifact; build_artifact()"`), не меняя `honest_metrics.csv`.
6. Отдельного оптимизатора состава для v2 нет. Старый оптимизатор в режиме v2 выключен, потому что писал прогноз в обучающие данные.
7. `so2` (0.53) и `co` (0.57) ниже лучшего бустинга опубликованного аудита. Узкая сетка GB этот разрыв не закрыла. Это не эффект парсера: `kt` совпадает с аудитом (0.834).
8. Признаки `phys_*` и синергии выключены: не проверено, что таблица компонентов не содержит те же рецептуры.
9. Давления, влажности и фракции в 48 рецептурах нет.
10. Доступ установки GitHub App к `sdv301/Tolko_model` на момент интеграции по-прежнему отсутствовал. Если снимок и ветка разъедутся, артефакт нужно пересобрать из нового снимка, а не из этого joblib.
