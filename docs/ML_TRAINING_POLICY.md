# Регламент обучения ML-моделей в Pellets Analyzer

## 1. Архитектурный принцип

В production-окружении веб-приложение Pellets Analyzer работает в режиме **инференса по зафиксированным артефактам** (`MODEL_VERSION=v2`, артефакты в `models/v2`, синхронизированные с субмодулем `lab` на коммите `PIN`).

Для предотвращения деградации производительности, зависания воркеров Gunicorn и аварийного завершения контейнеров по OOM / таймауту:
1. **Любое обучение внутри веб-воркера строго запрещено.**
2. Эндпоинты управления обучением и модификации обучающей базы (`/ml_system_train`, `/ml_auto_retrain`, `/ml_augment_database` и `/ml_load_excel`) защищены серверным гейтом и доступны **исключительно роли `admin`**. При этом в веб-воркере обучение не стартует: эндпоинты возвращают информативный отказ со статусом и указанием CLI-команды для офлайн-запуска.
3. Эндпоинт оптимизации рецептур (`/ml_optimize`) **не является обучением модели**. Он выполняет быстрый математический подбор долей сырья по зафиксированной модели (SciPy SLSQP / L-BFGS-B в v2) и доступен **всем авторизованным пользователям** (включая операторов и лаборантов) для работы с рецептурами в калькуляторе.
4. Для роли `operator` доступен инференс (`/api/predict_composition`, `/ml_predict`), оптимизация состава (`/ml_optimize`), сверка с лабораторией и сохранение рецептур (`/api/ml/save_recipe`).

## 2. Процедура переобучения для администратора

Обучение и обновление весов ML-моделей выполняется **исключительно вне request-path веб-сервера**:

### Способ 1: Сборка артефакта v2 через CLI (основной)
```bash
# 1. Обновление субмодуля лаборатории
git submodule update --init lab

# 2. Сборка валидированного артефакта v2 (прогон nested CV, генерация метрик, калибровка)
python scripts/build_v2_artifact.py --out models/v2

# 3. Перезапуск веб-сервиса с предзагрузкой (--preload)
docker compose restart web
```

### Способ 2: Офлайн-обучение legacy моделей через CLI
Для автономного переобучения устаревших legacy-моделей (без блокировки Gunicorn):
```bash
python scripts/train_legacy.py --algorithm random_forest --db-path data/pellets_data.db
```

### Способ 3: Shadow-режим (теневое тестирование)
При тестировании новых версий активируется флаг `ML_SHADOW_V2=1`. При каждом расчёте рецепта система параллельно выполняет теневой расчёт и логирует расхождения в таблицу `ml_shadow_logs` без блокировки основного потока.

## 3. Таблица прав доступа к ML-эндпоинтам

| Эндпоинт | Метод | Роль | Назначение |
|----------|-------|------|------------|
| `/api/predict_composition` | POST | Все авторизованные | Быстрый расчёт свойств пеллет по долям сырья |
| `/ml_predict` | POST | Все авторизованные | Расчёт конкретного параметра |
| `/ml_optimize` | POST | Все авторизованные | Подбор оптимального состава (инференс/SciPy по фиксированной модели) |
| `/api/ml/save_recipe` | POST | Все авторизованные | Сохранение рецепта и невязок в БД |
| `/api/ml/saved_recipes` | GET | Все авторизованные | История сохранённых рецептур |
| `/ml_system_train` | POST | **Admin only** | Проверка статуса (обучение в веб-воркере заблокировано, запуск через CLI) |
| `/ml_auto_retrain` | POST | **Admin only** | Заблокировано в веб-воркере (запуск через CLI) |
| `/ml_augment_database` | POST | **Admin only** | Генерация синтетических данных |
| `/ml_load_excel` | POST | **Admin only** | Пакетный импорт данных |

## 4. Политика хранения и ротации артефактов (Retention Policy)

Для предотвращения переполнения дискового пространства в production-контейнере настроена политика ротации:
1. **Зафиксированные артефакты v2 (`models/v2/`):** являются постоянными и неприкосновенными. Автоматическая очистка к ним не применяется. Обновление выполняется исключительно через `scripts/build_v2_artifact.py`.
2. **Неактивные legacy-модели (`app/services/models/`):** дампы моделей (`*.joblib`, `*.pkl`) старше 30 дней автоматически очищаются при запуске контейнера через `entrypoint.sh`.
3. **Временные файлы загрузок и сессий:** файлы в `Uploads/` старше 7 дней и истекшие сессии в `sessions/` старше 14 дней удаляются автоматически.
